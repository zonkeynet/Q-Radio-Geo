Caltrans metadata was collected around 03:10 Europe/Rome; Norwegian metadata at

The final integrated audit has 159 events, of which seven were locally interrupted.
Interrupted attempts remain auditable but do not supersede completed evidence.
A changed query token alone does not establish progress. HTTP 200 alone does not
establish live video. The checker compares the same media-playlist URL after at
least twice the target duration plus one second, then inspects a bounded segment
prefix. MPEG-TS or a structurally sufficient fMP4 fragment is required. No media
files are retained. Large target durations may leave a bounded check inconclusive.

These observations do not certify availability now, physical capture time,
placeholder/replay absence, browser CORS on every resource, Tor reachability or
Android decoding. A real browser/device playback test remains necessary; local
Chromium could not start in this execution environment.

## Application behavior

WEBCAMS has filters for video/images, verification state, and country. Country
names, road search and Norway aliases are available. Source attribution and usage
terms are visible in the card; the web exposes links to the source and licence.

Catalog loading, searches and globe movement make no camera-provider media requests.
The web first opens a local card, and Play/Load starts the connection. Close, Stop,
layer switching and hiding the page release the player. Returning does not restart
it. Buffer and retry limits are bounded. A snapshot loads once without refresh.

Android HLS uses the existing native `kind=tv, hls=true` bridge. The native player
continues to own consent, public-address validation, redirects and routing. Images,
MJPEG, RTSP, YouTube and iframes are not sent through that HLS path. Browser HLS
requires HTTPS and compatible CORS. One Caltrans HTTP HLS URL is not silently
rewritten to HTTPS. No blanket proxy or central stream relay was introduced.

## Data pipeline and software verification

- `scripts/build_webcams.py`: official Caltrans collection, normalization, approved
  additional catalog import, dated evidence merge, geographic comparison and exports.
- `scripts/collect_vegvesen.py`: reproducible Norwegian OGC collection and normalization;
  offline by default, with source receipt, digest and completeness checks.
- `scripts/check_webcams.py`: resumable provider-specific HLS checking. Use
  `--provider caltrans` or `--provider vegvesen`; origins come from fixed code policy.
- `data/webcams.json`: integrated UI catalog, schema version 1.
- `db/qp1ng-webcams.sqlite.gz`: compressed companion database with sources, metadata,
  public_webcams, webcam_streams, webcam_stream_links and osm_candidate_links.

Extra input files cannot approve providers, hosts or rights. Imported health flags
are discarded and only explicit probe evidence updates status. Malformed JSONL
checkpoint lines retain their original bytes, emit warnings and are recorded in
`probe_parse_warnings.json`; invalid whole-document JSON still fails. The current
build has zero parse warnings. A segment 404 does not turn a successful master
request into a false master 404. Local cancellation preserves prior completed health.

Final checks: **42 Python tests and 11 JavaScript tests passed**, SQLite integrity
is `ok`, foreign-key violations are zero, and the frontend accepts all 4,523 records
with 81 in the dated-live filter. The original OSM SHA-256 is unchanged:
`04efcf12bf90fb113038a36765d77ef7cb273923eea93c0283a080436fcb34d2`.

## Reproduce or refresh

Python 3.10+ standard library, Node.js 18+ for tests. Work in the repository root.
These commands explicitly fetch metadata only; checking performs bounded media reads.
No scheduled job is enabled by this change.

```bash
python -c "import gzip,pathlib; pathlib.Path('work').mkdir(exist_ok=True); pathlib.Path('work/surveillance.sqlite').write_bytes(gzip.decompress(pathlib.Path('db/qp1ng-surveillance.sqlite.gz').read_bytes()))"
python scripts/collect_vegvesen.py --fetch --source-dir work/vegvesen --out work/vegvesen/normalizzato.json
python scripts/build_webcams.py --fetch --source-dir work/caltrans --extra-catalog work/vegvesen/normalizzato.json --osm-db work/surveillance.sqlite --audit-dir work/webcam_audit
python scripts/check_webcams.py --provider caltrans --catalog data/webcams.json --out work/caltrans_health.jsonl --mode live --limit 30 --budget-seconds 300
python scripts/check_webcams.py --provider vegvesen --catalog data/webcams.json --out work/norway_health.jsonl --mode live --limit 30 --budget-seconds 300
python scripts/build_webcams.py --source-dir work/caltrans --extra-catalog work/vegvesen/normalizzato.json --osm-db work/surveillance.sqlite --health work/caltrans_health.jsonl --health work/norway_health.jsonl --audit-dir work/webcam_audit
python -m unittest discover -s tests -p 'test_webcams*.py' -v
node --test scripts/test_webcams.mjs scripts/test_native_app.mjs
```

For the exact dated snapshot, use the retained raw catalogs and receipts, all probe
files listed in the evidence archive, and the explicit verified URL-repair file.
Do not refresh metadata if reproducing old counts. `--limit 0` considers all eligible
URLs within the time budget; subsequent runs skip sufficiently recent checks.
Prefer separate controlled maintenance jobs for each provider and retain timestamps.
